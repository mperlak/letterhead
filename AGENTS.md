# AGENTS.md — instructions for AI coding agents working in this repo

This repo is the source for the `letterhead` agent skill. All edits land under
`letterhead/` (the canonical mount). The mirror under `skills/letterhead/` is
regenerated by `bin/sync-mounts.sh`. **Never edit the mirror directly** — CI
fails on drift.

## Editing workflow

1. Make changes only under `letterhead/`.
2. Run `bin/sync-mounts.sh` to regenerate the mirror.
3. Commit the canonical change and the mirror update in the same commit.

## Adding content

- **Template** → `letterhead/templates/<slug>/template.md`. Frontmatter, use /
  do-not-use rules, structure, hierarchy contract, mobile contract, review
  contract, failure modes. Keep it compact.
- **Style** → `letterhead/styles/<slug>/{DESIGN.md,tokens.css}`. DESIGN.md is
  Stitch-format (YAML frontmatter + six numbered prose sections); tokens.css
  carries the full CSS token surface in all three selector blocks (`:root`,
  `[data-theme="dark"]`, and the `prefers-color-scheme` fallback). Validate
  tokens with `node letterhead/scripts/check-tokens.mjs <tokens.css>`.
- **Reference doc** → `letterhead/reference/<topic>.md`. Lean procedure and
  named failure modes only.

## Checks and bundled libraries

`scripts/check-document.mjs` checks a finished HTML document and
`scripts/check-tokens.mjs` checks a `tokens.css`; both exit 2 on errors.
`scripts/vendor/` holds culori and node-html-parser bundled from npm; rebuild
them with `bash dev-scripts/build-vendor.sh`, never edit them by hand (see
`letterhead/NOTICES.md`).

## Authoring rules

See `letterhead/AUTHORING.md` for the writing conventions (voice, constraint
discipline, what belongs in SKILL.md vs reference files). The short version:
every constraint must name the bad output it prevents, SKILL.md stays
procedural, reference docs never restate SKILL.md.

## Repository layout

```
letterhead/                 ← canonical mount, the only directory anyone edits
├── SKILL.md
├── AUTHORING.md            ← contributor guide (voice, constraint discipline)
├── NOTICES.md              ← bundled libraries and their licenses
├── reference/              ← create / teach / publish procedures
├── templates/              ← template contracts (template.md per template)
├── styles/                 ← styles (DESIGN.md + tokens.css per style)
├── fixtures/               ← Lumen/Atlas demo source documents
└── scripts/                ← checkers, brand scripts, vendor/ bundles

skills/letterhead/          ← byte-identical mirror for `npx skills add`
examples/                   ← generated demo documents + brand profiles
dev-scripts/                ← matrix builder, smoke tests, build-vendor.sh (not shipped)
                            ← build-gallery.mjs: the Pages gallery in temp/site/ (pages.yml)
                            ← screenshots.mjs (uniform 4:5 light/dark webp thumbnails, --all, --grid) and
                            ← contact-sheet.mjs (3x3 styles sheet), both on lib/shoot.mjs (headless shell + cwebp)
bin/sync-mounts.sh          ← regenerate the mirror (--check in CI)
bin/check-html.mjs          ← tag-closure check for fixtures/examples
.claude-plugin/             ← Claude Code plugin + marketplace manifests
.codex-plugin/              ← Codex plugin manifest
.agents/plugins/            ← Codex marketplace catalog
.github/workflows/ci.yml
```

## Releasing

Plugin hosts update only when the version changes. Bump `version` in
`letterhead/SKILL.md`, `.claude-plugin/plugin.json` and
`.codex-plugin/plugin.json` together, in the same commit, then run
`bin/sync-mounts.sh`. Check the Claude Code manifests with
`claude plugin validate .`.
