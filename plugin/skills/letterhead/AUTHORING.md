# AUTHORING.md — how to edit this skill

Rules for contributors (human or agent) editing the `letterhead/` mount.

## Voice

Plain, conversational English. Short sentences. Say what a thing does, not
how impressive it is. No filler vocabulary (delve, crucial, robust,
comprehensive, seamless, leverage). Avoid em-dashes in user-facing copy.
Promise only what exists; anything planned is labeled planned.

## Constraint discipline

Every rule in SKILL.md, a reference file, or a template must name the bad
output it prevents. "Consistency" is not a failure mode. If you cannot
describe the concrete bad document a constraint stops, the constraint is
defensive scaffolding; drop it.

## Where content lives

- **SKILL.md** carries routing, the shape gate, the bans, the review-ready
  contract, brand precedence, and the universal laws. Procedure lives in
  `reference/`. Do not duplicate; duplicated rules drift.
- **Reference docs** open with "apply the shared rules in SKILL.md" and
  then carry only their own procedure and failure modes.
- **Templates** (`templates/<slug>/template.md`) are contracts: frontmatter
  (name, description), Use when, Do not use when, Structure, Hierarchy
  contract, Mobile contract, Review contract, Failure modes. Keep them
  compact; the brand profile and universal laws handle everything a
  template does not say.
- **Styles** (`styles/<slug>/`) are worked examples for `teach` to borrow
  from, organized by document audience (who receives the document), not by
  aesthetic family. Each is a Stitch-format `DESIGN.md` plus a complete
  `tokens.css` (all three selector blocks). Validate token changes with
  `node scripts/check-tokens.mjs styles/<slug>/tokens.css`.

## Checks and libraries

`scripts/check-document.mjs` checks a finished document (review-ready
contract, visible leftovers, accessibility, contrast, theme contract) and
`scripts/check-tokens.mjs` checks a `tokens.css` (theme blocks, OKLCH,
gamut, contrast); a new rule goes into one of them with a name, a severity
and the bad document it stops. `scripts/vendor/` holds culori and
node-html-parser bundled from npm by `dev-scripts/build-vendor.sh`; rebuild
them with that script, never by hand, and update `NOTICES.md` if a version
changes.

## Review-ready is the identity

Any new template must include a Review contract section and honor the four
rules in SKILL.md § Review-ready contract. A template that produces
documents whose heading ids churn between versions is broken, whatever else
it does well.

## Repository mechanics

The canonical mount is `letterhead/` at the repo root; `skills/letterhead/`
is a byte-identical mirror regenerated by `bin/sync-mounts.sh`. Edit only
the canonical mount, run the sync, commit both. CI enforces drift, syntax,
token, document, and tag-closure checks (see `.github/workflows/ci.yml`).
