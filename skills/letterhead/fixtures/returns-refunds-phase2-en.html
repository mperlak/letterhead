1. Where Phase 1 left off

Phase 1 shipped the forward flow: orders placed in Lumen Commerce reach Atlas ERP within seconds, stock is reserved before confirmation, and order.paid events drive fulfillment. Returns still live entirely in email. A customer writes to support, support asks the warehouse, the warehouse checks Atlas, and a refund happens in Lumen days later — with no record connecting the three.

2. Phase 2 scope

Self-service returns portal

Customers start a return from their order history in Lumen. Eligible items (within the return window, not final-sale) get a prepaid label. The return request is created in Atlas as an RMA the moment the customer submits.

Refund flows

When the warehouse receives and grades the item, Atlas emits rma.received. Lumen refunds automatically for grade A and B returns; grade C goes to a support queue with photos attached. Refunds always go to the original payment method.

Partial refunds

Supported per line item, not per unit fraction. Shipping fees refund only when the whole order is returned, matching the published returns policy.

3. Out of scope for Phase 2

  • Exchanges (an exchange is modeled as a return plus a new order).
  • In-store returns for online orders — Atlas point-of-sale work, tracked separately.
  • Refunds to store credit; the wallet feature has no confirmed timeline.
  • Cross-border returns beyond the EU (customs paperwork is manual today and stays manual).
