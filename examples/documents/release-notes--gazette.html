Lumen Order Sync

Release 1.4 · Production June 18, 2026 Changes from 1.3.2
Breaking change · action required

Sequence enforcement becomes the consumer's job

Release 1.4 stops guaranteeing ordered webhook retries. Consumers must now enforce the sequence field themselves: discard any delivery whose sequence is lower than the last one processed for that order. Deadline: before upgrading to 1.5, which removes the legacy ordering shim entirely.

Who is affected: every order.paid consumer. The Atlas ERP consumer shipped its sequence guard in May and needs no change. Migration is one comparison: if the incoming sequence is not greater than the stored one, acknowledge and drop. The webhook reference documents the field; it has been present on every delivery since 1.3.

Highlights

Apple Pay lands; retries get cheaper

  • Newapple_pay joins the payment.method values. Consumers that switch on the method should add the case; everyone else needs no change.
  • ChangedRetry backoff now caps at hourly instead of every 10 minutes after the first hour, cutting duplicate-delivery volume roughly in half for consumers recovering from outages.
Changes by area

The full ledger

Webhooks

  • NewThe X-Lumen-Attempt header carries the delivery attempt number, so consumers can log retries distinctly.
  • ChangedDead-letter parking (after the 24-hour retry budget) now alerts the shared integration channel instead of failing silently.
  • FixedSignature verification no longer fails on bodies over 1 MB; the HMAC now reads the raw stream instead of a buffered copy.

Reservations

  • ChangedRejected lines return public reason codes (OUT_OF_STOCK, UNKNOWN_SKU, DISCONTINUED) instead of internal field names. Consumers parsing the old strings must switch to the codes; the old strings remain in a deprecated detail field until 1.5.
  • FixedA reservation retried at the exact expiry boundary could log a spurious conflict; the hold window check is now inclusive.

Operations

  • NewThe reconciliation job publishes a nightly summary row (orders compared, divergences, resolution state) to the integration channel.
Known issues

Shipping imperfect, on purpose

  • Sandbox tenants may log a spurious secret-rotation warning at startup. Harmless; fix scheduled for 1.4.1.
  • The deprecated detail field on rejections is absent (not empty) when the reason is DISCONTINUED. Parsers reading it defensively are unaffected.

Rollout is automatic; no consumer deployment is required beyond the migration above. Report problems in the shared integration channel. Previous edition: Lumen Order Sync 1.3 release notes.
