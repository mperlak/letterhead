What changed and why

Customers can now start a return from their order history instead of emailing support. The moment they submit, the return exists in Atlas as an RMA, which removes the email-to-warehouse relay that loses a day per return today.

Stop 1

The order history entry point

Eligible items show a "Return item" action. Eligibility runs on the 30-day window and final-sale flags. Before: no return surface existed. See it: any staged order under 30 days old.

Stop 2

The RMA lands in Atlas instantly

Submitting creates rma.created in Atlas with the order reference and reason. Before: warehouse learned about returns from forwarded emails. See it: the RMA list in the Atlas staging tenant.

What deserves your attention

Two decisions made on your behalf

  • We defaulted the return window to 30 days for everyone; the loyalty-tier extension is still an open decision and changes eligibility logic.
  • Reason codes are free-text plus four presets for now; the warehouse asked for strict presets, which would drop the free-text field.

How to verify

  1. Log into staging with the reviewer account and open any order under 30 days old.
  2. Start a return for one item and submit with the "wrong size" preset.
  3. Open the Atlas staging RMA list: the return should appear within seconds with the order reference attached. Anything slower than a minute is wrong.

What happens on acceptance

Your yes opens the flag to internal orders (step 2 exit) and starts the label generation work. If it is not a yes, leave comments on the stops above; the next walkthrough version answers them.
