Order Sync Integration

Replacing the nightly batch with event-driven sync, in four phases behind a percentage ramp.

Status

Owner

Audience
Engineering leadership, Atlas operations

Summary

Orders reach Atlas in a nightly batch today, which oversells stock during campaigns. We replace the batch with event-driven sync in four phases behind a percentage ramp.

Scope boundary

In scope: order creation, stock reservation, payment confirmation. Out of scope: returns and refunds, catalog sync. Assumption: SKUs pre-exist in the Atlas item master.

Phases

  1. This week
    Sign-off. Engineering leadership and Atlas operations approve this plan.
  2. Weeks 1–2
    Event contract. Both teams sign the payload spec.
  3. Weeks 3–4
    Reservation flow. Stock is held within the 8-second SLA.
  4. Weeks 5–9
    Webhook and ramp. 5% to 100% with the batch as shadow.

Phase 1: event contract agreed

Both teams sign the payload spec. Done when the spec is committed to both repos.

Phase 2: stock reservation flow

Checkout reserves stock within the 8-second SLA, idempotent on retry. Done when an end-to-end order confirms in staging and duplicates never double-hold stock.
