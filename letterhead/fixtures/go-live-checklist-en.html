1. Pre-launch (T minus 1 week)

  • Atlas staging tenant mirrors production item master — Atlas IT
  • End-to-end order placed, reserved, confirmed, and fulfilled in staging — Lumen QA
  • Idempotency verified: duplicate order.paid deliveries create one fulfillment — Lumen engineering
  • Load test at 3× peak campaign volume, reservation p95 under 8s — Lumen engineering
  • Reconciliation job dry-run compared against last week's batch exports — Atlas ops
  • Support macros updated for the new "confirming your order" state — Lumen support

2. Launch day

  • Freeze Atlas item-master changes during the cutover window — Atlas ops
  • Enable event sync for 5% of orders; nightly batch keeps running as shadow — Lumen engineering
  • Compare shadow batch vs. live events after 2 hours; divergence must be zero — Integration team
  • Ramp to 50%, then 100% if error budget holds — Integration team
  • Disable batch export only after 100% has run clean for 24 hours — Atlas IT

4. Rollback plan

Rollback is a switch, not a deploy: setting ORDER_SYNC_MODE=batch re-enables the nightly export and stops event emission. Orders created during event mode keep their external_ref and reconcile normally. The only manual step is releasing any stock reservations younger than 30 minutes, for which Atlas ops has a runbook. Practice rollback once in staging before launch day.
